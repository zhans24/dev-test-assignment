# Задача 2. Онлайн-запись к мастеру

Бэкенд записи в салон: клиент выбирает мастера, услугу и время. Есть мастера с графиком работы, услуги с длительностью и уже существующие записи.

Все времена в графике — местное время Алматы (UTC+5). В хранилище и в ответах API время записей хранится в UTC (`2030-11-18T05:00:00.000Z`).

Текущее время берите из `src/clock.ts`: при проверке мы подменяем его через переменную `NOW`.

Хранилище в `src/store.ts` специально отвечает с задержкой, как настоящая БД. Задержку не убирайте.

## 1. Баг

Тест `overlaps: запись сразу после другой не пересекается` падает. Исправьте.

## 2. Свободные слоты

Допишите `getSlots`. Слоты идут с шагом 15 минут от начала рабочего дня. Слот подходит, если вся услуга:

- помещается в рабочее время;
- не пересекает перерыв;
- не пересекает активные записи мастера (отменённые не мешают);
- начинается позже текущего момента.

Между активными записями одного мастера оставляем минимум 7 минут на уборку. Это правило действует и при выдаче слотов, и при создании записи. Отменённая запись освобождает своё время и время на уборку.

`GET /masters/:id/slots?serviceId=s-cut&date=2030-11-18`

```json
{ "masterId": "m-1", "serviceId": "s-cut", "date": "2030-11-18", "slots": ["11:15", "15:00"] }
```

- нет `serviceId` или `date`, дата некорректная, мастер не оказывает эту услугу — `400`;
- нет такого мастера или услуги — `404`.

## 3. Создание записи

`POST /bookings`

```json
{
  "masterId": "m-1",
  "serviceId": "s-cut",
  "start": "2030-11-18T15:00:00+05:00",
  "clientPhone": "8 (701) 234-56-78"
}
```

- `start` — любая ISO-строка с часовым поясом;
- телефон — казахстанский мобильный. Принимаем `+7 701 234 56 78`, `87012345678`, `8 (701) 234-56-78` и подобное, сохраняем как `+77012345678`. Остальное — `400`;
- время должно совпадать с одним из свободных слотов, иначе `409` с `{ "error": "slot_unavailable" }`;
- успешный ответ — `201` с созданной записью.

Если два клиента одновременно бронируют одно и то же время, запись должна создаться только одна, второй получает `409`. Напишите на это тест.

## 4. Отмена

`DELETE /bookings/:id`

- запись переходит в статус `cancelled`, ответ `200` с записью;
- меньше чем за 2 часа до начала отменить нельзя: `409` с `{ "error": "too_late" }`;
- повторная отмена — `200`, без ошибки;
- нет такой записи — `404`.
